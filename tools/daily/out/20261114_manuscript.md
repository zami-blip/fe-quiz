### 問2 D1114A02　テクノロジ／システム構成（バックアップ）　

測定する技能: 事例の条件の読み取り　想定所要時間: 60秒（作問上の見積り）

あるファイルサーバでは、毎週日曜日の 23:00 にフルバックアップを取得し、月曜日から土曜日までは毎日 23:00 に差分バックアップを取得している。差分バックアップには、直前のフルバックアップの取得以降に変更されたデータを記録する。

木曜日の 10:00 にディスクが故障したので、水曜日の 23:00 の時点の状態にデータを復旧する。復旧に使うバックアップとして、必要最小限の組合せはどれか。

ア　日曜日のフルバックアップと水曜日の差分バックアップ
イ　日曜日のフルバックアップと月曜日・火曜日・水曜日の差分バックアップ
ウ　水曜日の差分バックアップだけ
エ　日曜日のフルバックアップだけ

**正解 ア**

差分バックアップは、直前のフルバックアップ（日曜日）以降に変更されたデータをすべて含む。水曜日の差分には月曜日から水曜日までの変更が入っているので、日曜日のフルバックアップを戻した後に水曜日の差分を戻せば、水曜日 23:00 の状態になる。イは、前回のバックアップ以降の変更だけを記録する増分バックアップの復旧手順で、差分方式では月・火の差分は不要（最小限ではない）。ウは、差分に含まれない（日曜日以降に変更されていない）データを戻せない。エは、月曜日から水曜日までの変更が戻らない。〔検算〕ファイルの変更パターンを2,000通り作って模擬し、日曜フル＋水曜差分の2つで水曜日の状態に一致すること、水曜差分だけでは一致しない場合があることを確認。

〔差分と増分の違い〕
| 方式 | 毎日のバックアップに記録するもの | 水曜日の状態への復旧に使うもの |
|---|---|---|
| 差分（この問題） | 直前のフルバックアップ以降の変更すべて | 日曜フル＋水曜差分 |
| 増分 | 前回のバックアップ以降の変更 | 日曜フル＋月・火・水の増分 |

誤答選択肢の理由:
- ア: 正解
- イ: 増分バックアップと取り違えた。差分は日曜日以降の変更をすべて含むので、月・火の差分は不要（最小限ではない）
- ウ: 差分には日曜日以降に変更されたデータしかなく、変更のないデータを戻せない
- エ: 月曜日から水曜日までの変更が戻らない

### 問3 D1114A03　ストラテジ／企業活動（会計・財務）　関連 D1113A05

〔計算の手順〕
| 手順 | 式 | 値 |
|---|---|---|
| 変動費率 | （1,800＋800）÷4,000 | 0.65 |
| 限界利益率 | 1－0.65 | 0.35 |
| 固定費 | 1,000＋300＋170 | 1,470万円 |

誤答選択肢の理由:
- ア: 限界利益率ではなく変動費率（0.65）で割った

### 問1 D1114B01　アルゴリズムとプログラミング／配列の探索　復習元 D1113B01

測定する技能: ループの回数と実際の添字の対応・折返し・連続条件の更新　想定所要時間: 270秒（作問上の見積り）

ある気象観測装置は、直近 n 日の最高気温を、要素数 n の配列 temp に記録する。1日分の値を記録するときは、最も古い日の値が入っている要素に新しい値を上書きする。変数 head には、最も新しい日の値が入っている要素番号が格納されている。最も古い日の値は要素番号 head ＋ 1 の要素に入っていて、head が n のときは要素番号1の要素に入っている。配列の要素番号は1から始まる。

関数 longestRun は、記録されている n 日分の値を、最も古い日から最も新しい日まで日付の順に調べ、最高気温が limit 以上だった日が連続した最も長い日数を返す。最も新しい日と最も古い日は連続した日ではない。また、x mod y は x を y で割った余りを表す。

配列 T と変数 h が次のとおりのとき、longestRun(T, h, 25) の戻り値はどれか。

T ＝ {27, 25, 23, 26, 29, 22, 28, 26}、h ＝ 5

〔プログラム〕

```
○整数型: longestRun(整数型の配列: temp, 整数型: head, 整数型: limit)
  整数型: n ← temp の要素数
  整数型: run ← 0
  整数型: best ← 0
  整数型: k, p
  for (k を 1 から n まで 1 ずつ増やす)
    p ← ((head ＋ k − 1) mod n) ＋ 1
    if (temp[p] ≧ limit)
      run ← run ＋ 1
      if (run ＞ best)
        best ← run
      endif
    else
      run ← 0
    endif
  endfor
  return best
```

ア　2
イ　3
ウ　4
エ　6

**正解 ウ**

n＝8、head＝5 なので、最も新しい日は要素5、最も古い日は要素6。p ＝ ((5 ＋ k − 1) mod 8) ＋ 1 は、k＝1 のとき6、k＝2 のとき7、k＝3 のとき8、k＝4 のとき1（要素8の次は要素1に戻る）… k＝8 のとき5 になる。日付の順の値は 22、28、26、27、25、23、26、29。25 以上が続くのは 28、26、27、25 の4日（要素7、8、1、2）で、要素3 の 23 で run が0に戻る。その後の 26、29 は2日。戻り値は4。アの 2 は、head を使わずに要素1から順に調べた場合（27、25 ／ 26、29 ／ 28、26 がそれぞれ2日）。イの 3 は、≧ を ＞ と読み、25 ちょうどの要素2を数えなかった場合（28、26、27 の3日）。エの 6 は、else の run ← 0 を読み落とし、25 以上の日を通算した場合。〔検算〕疑似言語を Python で再現して4を確認。別の手順として、head の次から並べ直した列で最長の連続日数を求めても4。ランダムな入力5,000件で両者が一致することを確認。各誤答の読み違いを再現したコードでもア・イ・エの値になることを確認。

〔追跡表（k は繰返しの回数、p は実際に調べる要素番号。各行は if 文の処理の後の値）〕
| k（回数） | p（要素番号） | temp[p] | 25以上か | run | best |
|---|---|---|---|---|---|
| 1 | 6 | 22 | × | 0 | 0 |
| 2 | 7 | 28 | ○ | 1 | 1 |
| 3 | 8 | 26 | ○ | 2 | 2 |
| 4 | 1 | 27 | ○ | 3 | 3 |
| 5 | 2 | 25 | ○ | 4 | 4 |

### 問2 D1114B02　アルゴリズムとプログラミング／キュー　関連 D1113B02

測定する技能: 取出し・末尾への再投入・終了条件と回数の追跡　想定所要時間: 300秒（作問上の見積り）

あるコールセンターでは、折り返しの電話を待つ顧客に、受付の順に電話をかける。応答がなかった顧客は待ち行列の末尾に並べ直し、ほかの顧客に電話をかけた後で、もう一度電話をかける。ただし、1人の顧客に電話をかける回数は maxTry 回までとし、maxTry 回かけても応答がなければその顧客への電話を打ち切る。

顧客には受付の順に1から番号が付いている。配列 need の要素 need[i] は、顧客 i が何回目の電話に応答するかを表し、0 はどの電話にも応答しないことを表す。配列の要素番号は1から始まる。

関数 callBack は、応答した顧客の番号を、応答した順に格納した配列を返す。待ち行列には顧客の番号を入れる。大域変数 calls は、電話をかけた回数の合計を数える。tries ← {need の要素数 個の 0} は、要素数が need と同じで、すべての要素が0の配列を生成する。

待ち行列は Queue型 で表す。Queue型: que ← 空のキュー によって要素のないキューを生成し、次の操作を使う。空のキューに対して dequeue を行うことはない。

〔Queue型の操作〕
| 操作 | 説明 |
|---|---|
| que.enqueue(x) | x をキューの末尾に追加する。 |
| que.dequeue() | キューの先頭の値をキューから取り除き、その値を返す。 |
| que.isEmpty() | キューが空であれば true を、そうでなければ false を返す。 |

関数 callBack を、need ＝ {2, 1, 0, 3}、maxTry ＝ 3 として呼び出したとき、戻り値と、関数の処理が終わった時点の calls の値の組合せとして正しいものを、解答群の中から選べ。ここで、呼び出す前の calls は0である。

〔プログラム〕

```
大域: 整数型: calls ← 0

○整数型の配列: callBack(整数型の配列: need, 整数型: maxTry)
  整数型の配列: done ← {}
  整数型の配列: tries ← {need の要素数 個の 0}
  Queue型: que ← 空のキュー
  整数型: i, j
  for (i を 1 から need の要素数 まで 1 ずつ増やす)
    que.enqueue(i)
  endfor
  while (que.isEmpty() が false と等しい)
    j ← que.dequeue()
    tries[j] ← tries[j] ＋ 1
    calls ← calls ＋ 1
    if (tries[j] が need[j] と等しい)
      done の末尾に j を追加する
    elseif (tries[j] ＜ maxTry)
      que.enqueue(j)
    endif
  endwhile
  return done
```
