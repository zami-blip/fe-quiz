ウ　172.20.116.1 ～ 172.20.119.254
エ　172.20.128.1 ～ 172.20.135.254

### 問3 D1113A03　テクノロジ／情報セキュリティ

測定する技能: 事例の条件と攻撃手順の照合（skill=事例判断）　想定所要時間: 80秒（作問上の見積り）

会員制の Web サイトは、利用者を識別するためにセッション ID を使っている。サイトの仕様は次の (a)～(c) である。

(a) セッション ID は Cookie で受け渡すが、URL のパラメータ sid で指定されたセッション ID も受け付ける。
(b) ログイン前の閲覧時にセッション ID を発行し、ログインに成功した後も同じセッション ID を使い続ける。
(c) 通信はすべて HTTPS で行い、Cookie には Secure 属性を付けている。

攻撃者は、自分でこのサイトにアクセスしてセッション ID を取得し、その ID を sid に指定した URL をメールで利用者に送った。利用者がその URL からサイトにアクセスしてログインした後、攻撃者は同じセッション ID を使い、利用者としてサイトを操作した。

この攻撃が成立するために必要な仕様の組合せと、この攻撃への対策として最も有効なものの組合せはどれか。

| 解答群 | 成立に必要な仕様 | 最も有効な対策 |
|---|---|---|
| ア | (a)と(b) | ログインに成功した時点でセッション ID を新しく発行し直す |
| イ | (a)と(b) | セッション ID を格納する Cookie に HttpOnly 属性を付ける |
| ウ | (a)だけ | ログインに成功した時点でセッション ID を新しく発行し直す |
| エ | (a)、(b)、(c)のすべて | 通信を HTTPS に限定する |

**正解 ア**

この攻撃はセッション固定（セッションフィクセーション）攻撃。攻撃者があらかじめ知っている ID を利用者に使わせ、利用者のログイン後もその ID が有効なままであることを利用する。成立には、外部から ID を指定させられること（(a)）と、ログイン後も同じ ID が使われ続けること（(b)）の両方が必要。(c) の HTTPS・Secure 属性は通信の盗聴を防ぐもので、この攻撃の成否に関係しない。対策は、ログインに成功した時点で ID を発行し直すこと。攻撃者の知っている ID はログイン前のものになり、ログイン後の操作に使えなくなる（URL パラメータの ID を受け付けないことも併せて有効）。イの HttpOnly 属性は、スクリプトから Cookie を読み出されることを防ぐ（主にクロスサイトスクリプティングによる ID の盗用への対策）。この攻撃では攻撃者が ID を最初から知っているので防げない。ウは、(b) がない場合にはログイン後の ID が新しくなり攻撃が成立しないことを見落としている。エは、成立に関係しない (c) を含め、対策も既に満たしている HTTPS を挙げている。〔検算〕仕様 (a)(b)(c) の有無の8通りで、攻撃者の知っている ID がログイン後の ID と一致するかを確認し、成立は (a)(b) がともにある場合だけ（(c) の有無に関係しない）であることを確認。


誤答選択肢の理由:
- ア: 正解
- イ: HttpOnly は スクリプトによる Cookie の読出しを防ぐ対策。攻撃者は ID をすでに知っているので防げない
- ウ: (b) がなければ、ログイン後の ID は攻撃者の知らない値になるので (a) だけでは成立しない
- エ: (c) は盗聴への対策で成立には不要。すでに HTTPS なので対策にもならない

### 問1 D1113B01　アルゴリズムとプログラミング／配列の探索

測定する技能: 説明と疑似言語の対応付け・添字の折返し・早期return（skill=追跡）　想定所要時間: 270秒（作問上の見積り）

あるレストランには、円形のテーブルに n 席が並んでいる。席には1から n までの席番号が付いていて、席 i（i ＜ n）の隣は席 i ＋ 1、席 n の隣は席1である。配列 seat の要素 seat[i] には、席 i が空いていれば0、使用中であれば1が格納されている。配列の要素番号は1から始まる。

関数 findSeats は、席1から席番号の順に席を調べ、空席が k 席続いたところで、その k 席のうち最初に調べた席の席番号を返す。席 n を調べた後は席1に戻って調べ続け、調べた回数が n ＋ k − 1 回になっても k 席続く空席が見つからなければ −1 を返す。ここで、1 ≦ k ≦ n とする。また、x mod y は、x を y で割った余り（x が0以上のとき、0以上 y 未満の値）を表す。

配列 A を次のとおりとするとき、findSeats(A, 3) と findSeats(A, 4) の戻り値の組合せとして正しいものを、解答群の中から選べ。

A ＝ {0, 0, 1, 0, 0, 0, 1, 0, 0}

〔プログラム〕

```
○整数型: findSeats(整数型の配列: seat, 整数型: k)
  整数型: n ← seat の要素数
  整数型: run ← 0
  整数型: i, p
  for (i を 1 から n ＋ k − 1 まで 1 ずつ増やす)
    p ← ((i − 1) mod n) ＋ 1
    if (seat[p] が 0 と等しい)
      run ← run ＋ 1
      if (run が k と等しい)
        return i − k ＋ 1
      endif
    else
      run ← 0
    endif
  endfor
  return −1
```

| ア | 2 | 2 |
| イ | 3 | 7 |
| ウ | 4 | −1 |
| エ | 4 | 8 |

### 問2 D1113B02　アルゴリズムとプログラミング／キュー

測定する技能: 取出し・再投入・繰返し回数と途中状態の追跡（skill=追跡）　想定所要時間: 300秒（作問上の見積り）

ある事務所では、複数の印刷ジョブを1台のプリンタで印刷する。1つのジョブを続けて長く印刷すると後のジョブが待たされるので、待ち行列の先頭のジョブを取り出して最大 q ページだけ印刷し、印刷し終わっていないジョブは待ち行列の末尾に並び直させる。

関数 printJobs は、ジョブ名を格納した配列 name、各ジョブの印刷するページ数を格納した配列 pages、1回に印刷する最大ページ数 q を受け取り、印刷し終わったジョブのジョブ名を、終わった順に格納した配列を返す。大域変数 turns は、ジョブを取り出して印刷した回数を数える。配列の要素番号は1から始まる。

待ち行列は Queue型 で表す。Queue型: que ← 空のキュー によって要素のないキューを生成し、次の操作を使う。空のキューに対して dequeue を行うことはない。

〔Queue型の操作〕
| 操作 | 説明 |
|---|---|
| que.enqueue(x) | x をキューの末尾に追加する。 |
| que.dequeue() | キューの先頭の値をキューから取り除き、その値を返す。 |
| que.isEmpty() | キューが空であれば true を、そうでなければ false を返す。 |

関数 printJobs を、name ＝ {"A", "B", "C", "D"}、pages ＝ {5, 2, 7, 3}、q ＝ 3 として呼び出したとき、戻り値と、関数の処理が終わった時点の turns の値の組合せとして正しいものを、解答群の中から選べ。ここで、呼び出す前の turns は0である。

〔プログラム〕

```
大域: 整数型: turns ← 0

○文字列型の配列: printJobs(文字列型の配列: name, 整数型の配列: pages, 整数型: q)
  文字列型の配列: done ← {}
  Queue型: que ← 空のキュー
  整数型: i, j
  for (i を 1 から name の要素数 まで 1 ずつ増やす)
    que.enqueue(i)
  endfor
  while (que.isEmpty() が false と等しい)
    j ← que.dequeue()
    turns ← turns ＋ 1
    if (pages[j] ≦ q)
      pages[j] ← 0
      done の末尾に name[j] を追加する
    else
      pages[j] ← pages[j] − q
      que.enqueue(j)
    endif
  endwhile
  return done
```
