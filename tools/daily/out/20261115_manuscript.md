### 問1 D1115A01　テクノロジ／システム構成（バックアップ）　復習元 D1114A02

測定する技能: 事例の条件の読み取り　想定所要時間: 70秒（作問上の見積り）

あるシステムでは、毎月1日の 2:00 にフルバックアップを取得し、2日以降は毎日 2:00 に差分バックアップを取得している。差分バックアップには、直前のフルバックアップの取得以降に変更されたファイルを記録する。

5日の 15:00 に障害が発生し、5日の 2:00 の時点の状態にファイルを復旧する。復旧に使うバックアップの組合せとして、必要最小限のものはどれか。

ア　1日のフルバックアップと5日の差分バックアップ
イ　1日のフルバックアップと2日・3日・4日・5日の差分バックアップ
ウ　5日の差分バックアップだけ
エ　4日と5日の差分バックアップ

**正解 ア**

差分バックアップには、直前のフルバックアップ（1日）以降に変更されたファイルがすべて入っている。1日のフルバックアップを戻した後に5日の差分を戻せば、5日 2:00 の状態になる。イは、前回のバックアップ以降の変更だけを記録する増分方式の手順。差分方式では5日の差分に2～4日の変更も入っているので、2～4日の差分は不要（最小限ではない）。ウ・エのように差分だけで復旧すると、1日以降に一度も変更されていないファイルは差分に入っていないので戻らない（障害で失われたまま、または壊れたままになる）。フルバックアップは必ず最初に戻す。〔検算〕ファイルの変更パターンを2,000通り作って模擬し、1日フル＋5日差分（アの2つ）で5日の状態にすべて一致すること、ウ・エは変更されていないファイルが戻らずほとんど一致しないことを確認。

〔組合せごとの復旧結果〕
| 戻すもの | 戻るファイル | 5日 2:00 の状態になるか |
|---|---|---|
| 1日フル＋5日差分 | 全ファイル（1日時点）＋1日以降に変更されたもの | なる（最小限） |
| 1日フル＋2～5日差分 | 同上（2～4日の差分は5日の差分に含まれる） | なるが最小限ではない |
| 5日差分だけ／4日・5日差分 | 1日以降に変更されたものだけ | ならない（変更されていないファイルが戻らない） |

誤答選択肢の理由:
- ア: 正解
- イ: 増分方式の手順と取り違えた。5日の差分に2日以降の変更がすべて入っているので、2～4日の差分は不要（最小限ではない）
- ウ: 差分には1日以降に変更されたファイルしかないので、変更されていないファイルが戻らない
- エ: 差分どうしを組み合わせても、1日以降に変更されていないファイルは戻らない

誤答選択肢の理由:
- ア: 目標利益を加えずに損益分岐点売上高を求めた

### 問1 D1115B01　アルゴリズムとプログラミング／キュー　復習元 D1114B02

測定する技能: 取出し・末尾への追加の追跡（指定回の直後の状態）　想定所要時間: 150秒（作問上の見積り）

ある工場では、加工待ちの部品の残り加工時間（分）を、待ち行列 que に並んだ順に格納している。加工機は、待ち行列の先頭の部品を取り出して最大3分加工する。残り加工時間が3分より長い部品は、残り加工時間を3分減らして待ち行列の末尾に並べ直す。3分以下の部品は加工を終える。

待ち行列は Queue型 で表し、次の操作を使う。キューの中身は { } の中に先頭から末尾の順に書く。例えば {5, 3} は、先頭が 5、末尾が 3 である。手続 process を呼び出すときに que が空になることはない。

〔Queue型の操作〕
| 操作 | 説明 |
|---|---|
| que.enqueue(x) | x をキューの末尾に追加する。 |
| que.dequeue() | キューの先頭の値をキューから取り除き、その値を返す。 |

que が {5, 3, 8, 2} のときに process(4) を呼び出した。4回目の繰返しの処理を終えた直後の que の中身はどれか。

〔プログラム〕

```
○process(整数型: k)
  整数型: i, x
  for (i を 1 から k まで 1 ずつ増やす)
    x ← que.dequeue()
    if (x ＞ 3)
      que.enqueue(x − 3)
    endif
  endfor
```

ア　{2, 2, 5}
イ　{2, 5}
ウ　{2, 0, 5}
エ　{5, 2}

**正解 イ**

1回目は先頭の 5 を取り出し、3 より大きいので 5 − 3 ＝ 2 を末尾へ（{3, 8, 2, 2}）。2回目は 3 を取り出し、3 ＞ 3 ではないので加工を終える（{8, 2, 2}）。3回目は 8 を取り出し、5 を末尾へ（{2, 2, 5}）。4回目は 2 を取り出して加工を終える（{2, 5}）。アは、3回目の直後の状態。ウは、x ＞ 3 を ≧ と読み、2回目に 3 − 3 ＝ 0 を末尾へ戻した場合（{8, 2, 2, 0} → {2, 2, 0, 5} → {2, 0, 5}）。エは、戻す値を先頭に入れると考え、先頭の部品を続けて加工した場合。〔検算〕疑似言語を Python で再現して {2, 5} を確認。キューを配列の切出しで表した別の実装でも同じ結果。各誤答の読み違いを再現したコードでもア・ウ・エの値になることを確認。

〔追跡表〕
| 回 | 取り出した値 | 処理 | 処理後の que（先頭→末尾） |
|---|---|---|---|
| 1 | 5 | 末尾へ 2 | {3, 8, 2, 2} |
| 2 | 3 | 加工終了 | {8, 2, 2} |
| 3 | 8 | 末尾へ 5 | {2, 2, 5} |
| 4 | 2 | 加工終了 | {2, 5} |

誤答選択肢の理由:
- ア: 3回目の処理の直後の状態を答えた（1回分少ない）
- イ: 正解
- ウ: x ＞ 3 を ≧ と読み、3 の部品を 0 にして末尾へ戻した
- エ: 戻す値をキューの先頭に入れると考えた

### 問2 D1115B02　アルゴリズムとプログラミング／配列の探索　復習元 D1114B01

測定する技能: 添字の折返しの追跡（指定回の添字と値）　想定所要時間: 150秒（作問上の見積り）

〔プログラム〕

```
○patrol(整数型の配列: val, 整数型: start, 整数型: step, 整数型: m)
```
