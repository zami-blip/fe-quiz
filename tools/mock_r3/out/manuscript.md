## M3A01　テクノロジ／基礎理論／8進数を16進数に変換する
skill=計算　難度=易　想定50秒

8進数の 3517 を16進数で表したものはどれか。

- ア　3517
- イ　74F
- ウ　DBD
- エ　E9E

**正解 イ**

解説：8進数の1桁は2進数の3桁に対応する。3517 → 011 101 001 111 → 2進数 11101001111。これを下位（右）から4桁ずつ区切ると 111 0100 1111 で、16進数の 7、4、F となり 74F。（10進数では 3×512＋5×64＋1×8＋7＝1871＝7×256＋4×16＋15）エの E9E は、2進数を上位（左）から4桁ずつ区切り、最後に0を補った場合（1110 1001 1110）。ウの DBD は、3517 を10進数とみなして16進数にした場合。アは、8進数の各桁をそのまま16進数の桁とした場合。

選択肢ごとの検算記録：ア：8進の各桁をそのまま使う／イ：正解／ウ：10進数とみなして変換／エ：上位から4桁ずつ区切る

## M3A02　テクノロジ／基礎理論／NAND素子だけで構成した論理回路の働き
skill=図表読解　難度=標準　想定90秒

図の論理回路の働きとして、適切なものはどれか。ここで、入力 A、B、C と出力 Y の値は0又は1とする。

〔図：図　論理回路〕（アプリではSVGで描画）図の構造：
- 入力は A、B、C の3本。
- G1 は A と B を入力とする NAND 素子、G2 は B と C を入力とする NAND 素子、G3 は C と A を入力とする NAND 素子。
- G4 は G1、G2、G3 の出力を入力とする3入力の NAND 素子で、その出力が Y。
- 線が交差しているだけの所（●がない所）は接続していない。

- ア　A、B、C が全て1のときだけ、Y が1になる。
- イ　A、B、C のうち1の個数が奇数のとき、Y が1になる。
- ウ　A、B、C のうち2つ以上が1のとき、Y が1になる。
- エ　A、B、C のうち少なくとも1つが1のとき、Y が1になる。

**正解 ウ**

解説：NAND は“全ての入力が1のときだけ0”。G1＝not(A and B)、G2＝not(B and C)、G3＝not(C and A)。Y は G1～G3 の NAND なので、G1～G3 のどれかが0のとき1になる。G1 が0になるのは A と B が両方1のときで、G2・G3 も同様。したがって Y＝(A and B) or (B and C) or (C and A) となり、2つ以上の入力が1のときに1になる（多数決回路）。例えば A＝1、B＝1、C＝0 では G1＝0 なので Y＝1 となり、アは誤り。A＝1、B＝0、C＝0 では G1～G3 が全て1で Y＝0 となり、イ・エは誤り（どちらも1になるはず）。〔検算〕入力8通りの全てで、回路の出力とウの条件が一致し、ア・イ・エはそれぞれ一致しない組がある。

選択肢ごとの検算記録：ア：AND と取り違え／イ：排他的論理和(パリティ)と取り違え／ウ：正解／エ：OR と取り違え

関数 nextGreater は、整数型の配列 a（要素数 n ≧ 1）を受け取り、要素ごとに“それより右側にあって、それより大きい値のうち、最も左にある値”を求めた配列 ans を返す。そのような値がない要素の ans の値は −1 とする。

配列 st をスタックとして使い、まだ答えが決まっていない要素の要素番号を st[1] から順に積む。top はスタックに積まれている要素番号の個数で、st[top] が一番上の要素番号である。条件式 x and y では、x が false のとき y は評価しない。

〔プログラム〕

```
○整数型の配列: nextGreater(整数型の配列: a)
  整数型: n ← a の要素数
  整数型の配列: ans ← {n個の −1}
  整数型の配列: st ← {n個の 0}
  整数型: top ← 0
  整数型: i
  for (i を 1 から n まで 1 ずつ増やす)
    while ((top ＞ 0) and (a[st[top]] ＜ a[i]))
      ans[st[top]] ← a[i]
      top ← top − 1
    endwhile
    top ← top ＋ 1
    st[top] ← i
  endfor
  return ans
```

a を次の配列として nextGreater を呼び出したとき、戻り値の配列と、処理の間に top がとる最大の値の組合せとして正しいものを、解答群の中から選べ。ここで、配列の要素番号は1から始まる。

| オ | {8, 8, 8, −1, 6, −1, −1, −1} | 3 |

解説：新しい値 a[i] が、スタックの一番上の要素番号の値より大きい間、その要素番号を取り出して答えを a[i] に決める。その後 i を積む（下の表）。i＝1～3：5, 3, 3 は一番上の値より大きくないので積むだけ（top＝3）。i＝4：8 は 3, 3, 5 のいずれより大きいので、要素番号3, 2, 1 の順に取り出して ans を8に決め、4を積む（top＝1）。i＝5：2 を積む（top＝2）。i＝6：6＞2 なので要素番号5を取り出して ans[5]＝6、次の一番上の a[4]＝8 は6より大きいので止め、6を積む（top＝2）。i＝7：6 は一番上の a[6]＝6 と等しく、＜ を満たさないので取り出さずに積む（top＝3）。i＝8：1 も取り出さずに積むので top＝4。最後までスタックに残った要素番号4, 6, 7, 8 の ans は −1 のまま。戻り値は {8, 8, 8, −1, 6, −1, −1, −1}、top の最大値は4。アは、比較を ≦ と読んだ場合で、i＝3 で等しい3が要素番号2を取り出して ans[2]＝3、i＝7 で ans[6]＝6 となり、top の最大は3。ウは、ans に値 a[i] ではなく要素番号 i を記録したと読んだ場合（ans[1]～ans[3] が4、ans[5] が6）。エは、while を1回だけ判定する if と読んだ場合で、i＝4 で要素番号3だけを取り出すため、ans[1]、ans[2] が −1 のまま残り、top の最大は6になる。オは、戻り値は正しいが、top の最大を“積む前の top”だけで数えた場合（i＝8 で積む前は3）。〔検算〕問題文のコードと、各読み違いを再現したコードを実行して確認。要素数1～10・同じ値を含む3,000件で、戻り値が仕様（右側で最初に現れる、より大きい値）と一致する。

## M3B07　アルゴリズムとプログラミング／キュー／キューを使って直近 k 個の値の和を順に求める

関数 windowSums は、整数型の配列 data と整数 k（1 ≦ k ≦ data の要素数）を受け取り、data の連続する k 個の値の和を、先頭の k 個から1つずつずらして順に求め、その並びを配列で返す。

配列 q をキューとして使う。q の末尾に追加することをキューへの格納とし、q[head] がキューの先頭（最も古い値）である。head を1増やすことを、キューからの取出しとする。キューに入っている値の個数は q の要素数 − head ＋ 1 である。変数 s には、キューに入っている値の和を保持する。

〔プログラム〕

```
○整数型の配列: windowSums(整数型の配列: data, 整数型: k)
  整数型の配列: q ← {}
  整数型の配列: res ← {}
  整数型: head ← 1
  整数型: s ← 0
  整数型: i
  for (i を 1 から data の要素数 まで 1 ずつ増やす)
    q の末尾に data[i] の値を追加する
    s ← s ＋ data[i]
    if (q の要素数 − head ＋ 1 ＞ k)
      s ← s − q[head]
      head ← head ＋ 1
    endif
    if (i ≧ k)
      res の末尾に s の値を追加する
    endif
  endfor
  return res
```

解説：値を1つ格納するたびに s に加え、キューの中が k＝3 個を超えたら、先頭の値を s から引いて取り出す。i が3以上になったら s を res に追加する（下の表）。i＝3 で 4＋7＋1＝12。i＝4 で8を加えると4個になるので、先頭の q[1]＝4 を引いて取り出し 7＋1＋8＝16（head＝2）。i＝5 で 1＋8＋2＝11（head＝3）、i＝6 で 8＋2＋6＝16（head＝4）。戻り値は {12, 16, 11, 16}、head は4。アは、取り出す条件を ≧ k と読んだ場合で、キューに2個しか残らないため2個ずつの和 {8, 9, 10, 8} になり、head は5。ウは、res に追加する条件を i ＞ k と読み、最初の和12を落とした場合。イは、head を先に1増やしてから s から q[head] を引いた場合で、先頭ではなく2番目の値を引く。i＝4 で 20−q[2]＝13、i＝5 で 15−q[3]＝14、i＝6 で 20−q[4]＝12 となる。オは、head ← head＋1 を読み落とした場合で、毎回 q[1]＝4 を引くため、i＝5 で 16＋2−4＝14、i＝6 で 14＋6−4＝16 となり、head は1のまま。〔検算〕問題文のコードと、各読み違いを再現したコードを実行して確認。要素数1～9・k をいろいろに変えた2,000件で、戻り値が連続する k 個の和の並びと一致する。

このプログラムでは、次の規則で値を受け渡す。

    if (v[i] ＞ 10)
      v[i] ← v[i] ÷ f
      c ← c ＋ 1
    endif
  endfor
  f ← f ＋ 1
  return c

  整数型: i
  for (i を 1 から v の要素数 まで 1 ずつ増やす)

  endfor
  return w

○main()

  整数型の配列: q ← copyOf(p)
  整数型の配列: r ← p
  整数型: f ← 2
  整数型: c1 ← halve(p, f)
  整数型: c2 ← halve(r, f)
  p と q と c1 ＋ c2 と f を出力する
```

  整数型: cur ← head
  整数型: nxt
  while (cur ≠ 0)
       a
       b
    prev ← cur
       c
  endwhile
  return prev
```

条件式 x and y では、x が false のとき y は評価しない。

全ての節で“親の値 ≦ 子の値”が成り立つ木を最小ヒープという。手続 downHeap は、根 h[1] 以外は最小ヒープの条件を満たしている h を受け取り、根の値を子と入れ替えながら下ろして、全体を最小ヒープにする。入れ替える相手は、2つの子のうち値の小さい方とする（子が1つならその子）。

例えば、h が {9, 3, 4, 5, 7, 6, 8}、n が7のとき、9を子の小さい方の3と入れ替え、次に子の5・7のうち小さい5と入れ替えて、h は {3, 5, 4, 9, 7, 6, 8} になる。

〔プログラム〕

```
○downHeap(整数型の配列: h, 整数型: n)
  整数型: i ← 1
  整数型: c, tmp
  while (2 × i ≦ n)
    c ← 2 × i
    if ((c ＋ 1 ≦ n) and (   a   ))
      c ← c ＋ 1
    endif
    if (h[i] ≦ h[c])
      return
    endif
    tmp ← h[i]
    h[i] ← h[c]
    h[c] ← tmp
    i ←   b
  endwhile
```

| 解答群 | a | b |
|---|---|---|
| ア | h[c ＋ 1] ＞ h[c] | c |
| イ | h[c ＋ 1] ＜ h[c] | 2 × i |
| ウ | h[c ＋ 1] ＜ h[c] | i ＋ 1 |
| エ | h[c ＋ 1] ＞ h[c] | 2 × i |
| オ | h[c ＋ 1] ＜ h[c] | c |
| カ | h[c ＋ 1] ＞ h[c] | i ＋ 1 |

**正解 オ**

解説：a：c は左の子の要素番号。右の子があり、右の子の値の方が小さければ右の子を選ぶので、h[c ＋ 1] ＜ h[c]。b：入れ替えた値は要素番号 c に移ったので、次はそこから調べる（i ← c）。a を h[c＋1] ＞ h[c]（ア・エ・カ）とすると、大きい方の子と入れ替えるので、入れ替えた後の親がもう一方の子より大きくなり、条件が崩れる（例で9と4を入れ替えると、親の4が左の子3より大きい）。b を 2 × i（イ）とすると、右の子と入れ替えた場合にも左の子の位置に進んでしまい、下ろした値を追いかけられない。b を i ＋ 1（ウ）とすると、子ではなく隣の節に進む。〔検算〕要素数1～15の最小ヒープの根をランダムな値に置き換えた2,500件で、処理後に最小ヒープの条件を満たし、値の集まりが変わらないのはオだけ。

選択肢ごとの検算記録：ア：大きい方の子と入れ替える／イ：常に左の子の位置へ進む／ウ：隣の節へ進む／エ：大きい方の子・左の位置へ進む／オ：正解／カ：大きい方の子・隣の節へ進む

## M3B18　情報セキュリティ／クラウド設定／クラウドの受信ルールが要件を満たしているかの点検
skill=判断　難度=標準　想定300秒

C社は、IaaS上にWebシステムを構築している。IaaSでは、サーバごとにセキュリティグループ（以下、SGという）を割り当て、SGの受信ルールで許可した通信だけをサーバが受信できる。受信ルールに一致しない通信は全て拒否される。許可した通信の応答は、送信のルールに関係なく返送される。

SGの受信ルールの送信元には、IPアドレスの範囲（CIDR表記）か、SGの名前を指定できる。SGの名前を指定した場合は、そのSGを割り当てたサーバからの通信だけが一致する。

選択肢ごとの検算記録：ア：機能が無効の S3 も含める／イ：1.x 系の S4 も含める／ウ：版を文字列で比べて S2 を含める／エ：S2・S3・S6 も含める／オ：2.0.0 を範囲外と考える／カ：正解／キ：修正済みの 2.3.4 も含める／ク：S2 と S3 も含める
